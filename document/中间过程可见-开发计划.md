## Phase 0 — 前置验证（不改协议、不改行为）

目的：把设计里的两个"未验证"变成事实。这两项都可能改变 Phase 1 的字段设计，所以必须先做。

### T0.1 实测硅基流动思考参数

- **做什么**：用 curl 直连 `https://api.siliconflow.cn/v1/chat/completions`，模型 `deepseek-ai/DeepSeek-V3.2`，尝试候选参数：`enable_thinking` / `thinking_budget` / `thinking: {"type":"enabled"}`，观察响应里是否出现 `reasoning_content` 字段。
- **验收标准**：确定 (a) 是否需要显式开参、参数名与取值；(b) 流式 `delta` 里的 reasoning 字段名。
- **产出**：结论写入 `document/中间过程可见-设计方案.md` R1 行，去掉"未验证"标记。
- **失败处理**：若该模型不支持思考，则改用支持 reasoning 的模型（如 `deepseek-ai/DeepSeek-R1` 系列）并更新 `config.py` 默认值方案。

### T0.2 TTFT 埋点

- **做什么**：
  1. `agent-app/src/agent_app/api/v1/chat.py` 的 `_stream_chat` 内打 4 个 `time.perf_counter()`：t0 `chat()` 入口、t1 `_store_user_message` 后、t2 `_initial_messages` 后、t3 首个转发的 chunk。
  2. `agent-app/src/agent_app/llm/call_log.py` 的 `ModelCallLogger` 增加 `on_llm_new_token`，记录首 token 时间戳，按 `node=` 拆分 `SummarizationMiddleware.before_model` 与 `model`。
- **验收标准**：日志中能看到 `t0→t1`、`t1→t2`、`t2→t3` 以及两次 LLM 调用的首 token 耗时。
- **约束**：只在 `DEBUG=true` 时输出；不引入新依赖；不改协议。
- **产出**：判断摘要那次 LLM 往返是否为首字延迟主因 → 决定 `compaction` 事件是否必须提前发。

## Phase 1 — 后端 block 事件流

### T1.1 保留 reasoning（`llm/client.py`）

- 新增 `ChatOpenAIWithReasoning(ChatOpenAI)`，override `_convert_chunk_to_generation_chunk`，把 `choices[0].delta.reasoning_content` 写入 `result.message.additional_kwargs["reasoning_content"]`。
- `get_llm()` 改用它；`get_summary_llm()` **不变**。
- 增加思考开关配置项，默认 `False`，通过 `extra_body` 透传。
- **验收**：`ChatOpenAIWithReasoning` 在思考关闭时行为与 `ChatOpenAI` 完全一致（不产生新字段）；开启时 chunk 上出现 `additional_kwargs["reasoning_content"]`。
- **依据**：`langchain_openai/chat_models/base.py:1609`（可 override 的实例方法）、`base.py:472-550`（白名单转发，保证不回喂）。

### T1.2 协议 schema（`schemas/chat.py`）

- 新增 `StreamKind`、`StreamBlockStatus`、`StreamStatus`、`StreamBlockOut`、`StreamStateOut`。
- 字段严格对应设计方案 §5.2 / §5.3 / §6.2。
- **验收**：字段名与设计文档逐字一致；不含任何展示层逻辑。

### T1.3 本轮聚合态（`core/stream_state.py` 新增）

- `load(session_id)` / `start(session_id, run_id)` / `put_block_start` / `put_delta` / `put_block_stop` / `put_reset` / `put_compaction` / `put_finish(status)`
- 复用 `core/redis.py:13` 的 `get_redis()`。
- Key `chat:stream:{session_id}`，TTL 30 min。
- **fail-soft**：所有异常捕获后记 warning 返回，绝不抛出（模块 docstring 必须写明与 `core/token_store.py` 的 fail-closed 差异）。
- delta 内存累积 + 200ms flush；block 边界立即 flush。
- **验收**：Redis 停止时，`POST /chat` 全流程正常、无异常抛出、无 500。

### T1.4 分片分类与状态机（`api/v1/chat.py`）

- `_chunk_text`（`:79`）→ `_blocks_from(chunk) -> list[tuple[str, str]]`
- `_stream_chat`（`:495`）内新增 block 状态机：`block-start` / `block-delta` / `block-stop`；`reset`；`compaction`。
- **保留** `chat.py:523` 的 `langgraph_node != _MODEL_NODE` 过滤。
- `_persist_reply`（`:457`）/ `_persist_interrupted`（`:480`）**不改**。
- 不再发 `chunk` 事件。
- **验收**：
  - 思考关闭时，事件序列 = `session` → `block-start(text)` → `block-delta*` → `block-stop` → `done`
  - 思考开启时，多一个前置 `block-start(thinking)` / `block-stop(thinking)`
  - 中止时块 `status = "interrupted"`
  - 重试时首事件后出现 `reset`

### T1.5 回放接口

- 新增 `GET /api/v1/chat/{session_id}/stream-state`，返回 `StreamStateOut | null`。
- 鉴权复用 `_require_session`（`:591`）。
- **验收**：无记录返回 `null` 且 HTTP 200；跨用户访问返回 404。

### T1.6 后端自测

- 用 `curl -N` 打 SSE，人工核对事件序列与设计文档一致。
- 验证 `messages` 表行数与内容**未变**（对比改动前后同一轮对话）。
- **验收**：`messages` 表只多一条 user + 一条 assistant 正文，无新 role。

## Phase 2 — 前端渲染与回放

### T2.1 事件类型（`lib/api.ts`）

- `:9` `ChatStreamEvent` 改判别联合，覆盖全部 v1 事件。
- `:46` 白名单 → 未知 `type` 记 `console.debug` 并忽略。
- **验收**：后端发一个未知事件，前端不崩、控制台有 debug、其余流程不受影响。

### T2.2 block 状态机（`pages/ChatPage.tsx`）

- `Bubble`（`:22-35`）加 `blocks: Block[]`、`runId`。
- 新增不可变 block reducer：`block-start` / `block-delta` / `block-stop` / `reset`。
- **验收**：`reset` 只清 `blocks`，不清气泡本身，不影响 `retryTurn` 现有行为。

### T2.3 思考面板（`components/ThinkingBlock.tsx` 新增）

- 纯文本渲染（**不用** `MarkdownMessage`）
- 可折叠；流式中自动展开；首个 `text` 块开始时自动收起
- 收起后保留"已思考 N 秒"入口
- **验收**：思考长文本滚动流畅（无逐 token Markdown 重解析）

### T2.4 渲染性能

- delta 攒在 `useRef`，`requestAnimationFrame` 批量 flush setState。
- **验收**：思考分片高频时无掉帧卡顿；React DevTools 中不出现每分片一次 setState。

### T2.5 回放

- 挂载 / 切换 session 时 `GET stream-state`；有记录则渲染并标注 `status`。
- 老会话（无 blocks）从 `content` 造单个 `text` block。
- **验收**：生成中刷新页面 → 看到已生成的过程 + "本轮已中断" + 重试入口。

### T2.6 吸底

- `stickRef` 仅在已处于底部时跟随；思考块展开不强制吸底。
- **验收**：用户在思考过程中向上滚动，新分片到来不把视口拽回底部。

## 验证方式

```bash
# 后端语法与静态检查
cd agent-app && .venv/Scripts/python.exe -m compileall -q src

# 前端类型检查与构建
cd web-app && npm run build

# SSE 人工验证（需后端运行）
curl -N -X POST http://localhost:8000/api/v1/chat \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"message":"你好"}'
```

**回归红线**（必须人工确认）：

1. `messages` 表不出现新 role 或新语义行。
2. 摘要中间件的输出**不**进入用户气泡。
3. 中止 + 重试路径行为与改动前一致。
4. Redis 停止时对话仍可用。
